대상: $ARGUMENTS (비어 있으면 docs/specs/에서 최근 수정된 spec)

목표: 5. 작업을 순서대로 구현하고 3. 수용 기준을 검증한다.

## 1. 준비
- spec 파일과 docs/principles.md를 읽는다.
- 체크되지 않은 첫 task부터 시작한다.

## 2. task 반복 (하나씩)
- 구현한다. 범위 밖 항목은 구현하지 않는다.
- "검증:"을 실제로 실행한다. 통과하면 `- [x]`로 체크한다.
- 실패하면 고친 뒤 다시 검증한다. 검증 없이 체크하지 않는다.

## 3. 설계와 달라질 때
- 멈추지 않는다. 6. 결정 기록에 한 줄 추가한다:
  `- Tn: 변경 내용 (이유)`
- 단, 새 추상화(새 계층, 공통 모듈, 프레임워크, 외부 의존성)가
  필요하면 멈추고 사람에게 묻는다.

## 4. 마무리 (converge)
- 모든 task가 끝나면 AC를 하나씩 다시 검증한다.
- 결과를 출력한다:
  - AC1: 통과/실패 — 확인 방법과 결과
  - ...
- 결정 기록 요약과 남은 이슈를 함께 출력한다.
